Activity 02 of 05 · Debugging

Find the Bug

A bug is a mistake in a program. The tricky ones do not stop the program at all — it runs happily and gives you the wrong answer. Your job is to find which line is responsible.

🎯

What you will learn

That mistakes in programs are findable and fixable, and that finding them is a normal skill — not a sign that you are bad at this.

🕹️

How to play

Read a short program, work out which line causes the wrong result, and choose it. The explanation appears straight away.

⭐

Tip for scoring well

Work out what the program should do first, then find where it stops doing that. One question here is deliberately correct — read carefully.

The word "bug" has a real history

In 1947, engineers working on an early computer found an actual moth trapped inside a relay and taped it into the logbook with the note "first actual case of bug being found". The name stuck. Every program ever written has contained bugs — professional programmers spend more time finding them than writing new code.

Understanding it

Three kinds of bug you will meet

🚫

Wrong order

Every step is fine on its own, but they happen in the wrong sequence — like putting the tea bag in after pouring the water. The program usually still runs; the result is just wrong.

➗

Wrong instruction

A single command does something different from what was intended — subtracting where it should add, or dividing where it should take a remainder.

🎚️

Wrong starting value

A running total begins at the wrong number, so the answer is out by a fixed amount every single time. These are especially easy to miss.

How programmers actually hunt bugs

  1. Say what the program should do. You cannot spot a wrong answer if you do not know the right one.
  2. Be the computer. Work through the lines in order, writing down each value as it changes. Most bugs become obvious when the values are written out.
  3. Narrow it down. Halve the program: the bug is either before the middle or after it. Repeat. This is much faster than reading every line many times.
  4. Fix one thing at a time. Change a single line, then run again. Changing several things at once means you no longer know which change fixed it.

Reading it as real code

Here is the second question from this activity written out. The tea bag must go into the cup before the water is poured:

# wrong order
pour water into cup
put tea bag into cup

# correct order
put tea bag into cup
pour water into cup

Notice that the wrong version is not nonsense — it is a perfectly valid program that makes bad tea. Computers do not know what you meant; they only do what you wrote.
