Activity 03 of 05 · Conditions

If–Else Challenge

Every program that makes a decision uses a condition: "if this is true, do this; otherwise do that". Read each rule and predict which path the program will actually take.

🎯

What you will learn

How a program chooses between two paths, and why checking the conditions in the right order matters so much.

🕹️

How to play

Read the rule and the values, work out whether each condition is true or false, then choose the message that will appear.

⭐

The trap to watch for

The difference between > (greater than) and >= (greater than or equal to). One question here turns entirely on that difference.

Conditions are checked from the top down, and the first true one wins

This is the single most important rule in the activity. In a list of if / else if / else branches, the program checks each condition in order and stops at the first one that is true. Everything after it is skipped — even if it would also have been true.

Understanding it

How a program makes a decision

A condition is a question with only two possible answers: true or false. "Is the score greater than 50?" is either true or it is false — there is no third answer and no "maybe".

Real life is full of these. "If it is raining, take an umbrella — otherwise, do not." A program written with if–else does exactly that: it picks one of two paths and ignores the other completely.

Where beginners usually slip is not the idea but the exact wording of the question. Asking "is the score more than 50?" and asking "is the score 50 or more?" sound almost identical in everyday speech, but they give different answers when the score is exactly 50 — and a program will happily follow whichever version you actually wrote.

Reading it as real code

The vending machine question from this activity, in full:

money = 20

if money >= 30:
    print("Chips")
else if money >= 15:
    print("Biscuit")
else:
    print("Not enough money")

With money = 20: the first question (20 ≥ 30?) is false, so the program moves on. The second question (20 ≥ 15?) is true, so it prints "Biscuit" and stops. It never even looks at the third branch.

The two joining words: AND and OR

➕

AND — both must be true

"Unlock the chapter if the subject is a quiz and attendance is at least 75%." If either part is false, the whole condition is false. AND is strict.

🔀

OR — only one needs to be true

"Open the library if it is Saturday or Sunday." Because only one part needs to be true, OR can accidentally let through cases you did not intend. OR is generous — sometimes too generous.

Where this appears in everyday technology

A traffic signal that changes because a sensor says a car is waiting, a game that unlocks a level above a certain score, a phone that refuses to send a message when the battery is below 5% — every one of them is an if–else in action. Once you can read these conditions, you can see the logic underneath half the technology you use.
