Algorithm Maze

An algorithm is simply a list of steps, written in the right order. In this activity you write that list, press Run, and watch the robot follow it — one step at a time, in exactly the order you chose.

🎯

What you will learn

That a program is a sequence of steps, and that changing the order changes the result — sometimes completely.

🕹️

How to play

Add arrow commands to your list, press Run, and guide the robot from the start tile to the ⭐ without touching a wall.

⭐

How to score well

Fewer commands is better. Match the shortest possible route and you earn all three stars.

Hitting a wall is not a mistake — it is information

When the robot stops at a wall, the program has told you exactly which step is wrong and roughly where. That is what engineers call debugging, and it is the single most common thing programmers do all day. Press Remove last, fix that step, and run again.

Understanding it

Why this is the first thing every programmer learns

A computer has no common sense. If you tell it to walk into a wall, it will try to walk into the wall. It does not know that your intention was to go around. Everything a computer does, it does because a human wrote down the steps in an order that works.

That ordered list of steps has a name: an algorithm. When the list is written in a language the computer understands, it becomes a program. The maze shows this without a single line of code, because the arrow buttons are the program.

Notice what happens when you put a step in the wrong place. Nothing subtle happens — the robot stops against a wall. That directness is the reason this activity works so well as an introduction: cause and effect are visible in under a second.

Reading it as real code

The exact sequence you build in the maze would look like this if it were written as a program. Compare it with the arrow buttons you pressed — it is the same list, in the same order.

move right
move right
move down
move right
move up
move right
move right

The only difference is the words. Programmers use move() or similar, but the idea — steps, in order, executed one after another — is identical.

Try this before you move on

  • Deliberately write a wrong sequence. See how the robot stops at a wall, and work out from that where the wrong step is. This is the debugging skill the next activity uses.
  • Solve a level twice. First reach the star however you can, then find the route that uses the fewest commands. Under 3 stars, ask yourself which steps were unnecessary.
  • Say "step 1, step 2, step 3" aloud as the robot moves. Programs run in order, and saying the numbers out loud makes that obvious.
