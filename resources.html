Documentation & Deliverables

The four CEP deliverables

The CEP requires four documents. This page gives the structure of each one, shows which parts of this site supply the material for it, and lists every placeholder that must be filled with real information after the field visit.

Jump to placeholder checklist

Read this first

This site is a one-day/one-night prototype. The activities, the instruments and the analysis format are complete and working — that is what the prototype demonstrates. What it deliberately does not contain is any fabricated field evidence: no invented school, no invented students, no invented responses, no photographs, and no results presented as real. Every place where actual fieldwork must be entered is marked with [ placeholder text like this ].

Deliverable 1

Field Visit Report

A factual record of the visit itself — what happened, when, and who was involved.

Required structure

  1. Cover page — project title, college name, CEP topic 14, student names and roll numbers, academic year, date of submission
  2. Certificate — signed by the college guide/head of department
  3. Declaration — statement that the work is the students' own
  4. Acknowledgement — thanks to the guide and the host school
  5. Index — contents with page numbers
  6. Chapter 1 — Introduction — what the CEP requires for topic 14
  7. Chapter 2 — Objectives of the visit
  8. Chapter 3 — The host school — name, address, classes, student strength, [ details ]
  9. Chapter 4 — Date and schedule of the visit — with the timetable actually followed (use the session plan on Table 3.1)
  10. Chapter 5 — Resource persons — teachers and staff who helped, [ names ]
  11. Chapter 6 — Activities conducted — the five activities, with photographs or diagrams [ if permitted ]
  12. Chapter 7 — Participation — number of students present, classes represented, [ attendance ]
  13. Chapter 8 — Observations — what was noticed during the session
  14. Chapter 9 — Photographs — with captions [ only with written permission ]
  15. Annexure — attendance sheet, permission letter, the instruments used

Evidence to collect on the day

  • Signed attendance sheet with the class teacher's signature
  • Letter of permission from the school (taken in advance)
  • Photographs of the activities — only if permission was granted in writing
  • All completed survey, pre-test, post-test and feedback forms, numbered
  • Notes taken during the session by at least one team member (do not rely on memory afterwards)
  • The teacher's verbal observations — write them down the same day
  • Any difficulty encountered, recorded while it is still fresh

If photographs are not permitted

This is common and perfectly acceptable. Where photography is refused, the report should use the signed attendance sheet, a description of the room layout, and your own hand-drawn diagrams of the activities. State plainly in the report that photographs were not taken because permission was declined — an honest explanation is far better than an unusable or improperly obtained image.

Deliverable 2

Project Planning & Design Document

The plan produced before the visit — most of this already exists on this site.

Required structure

  1. Project title and team details
  2. Topic and syllabus reference — Topic 14, Coding through Games and Activities
  3. Problem statement → Section 1
  4. Need assessment → Section 2
  5. Objectives — project and learning objectives → Section 4
  6. Target beneficiaries — Class 6–9 students, with justification
  7. Methodology → Section 3
  8. Activity plan — the five activities and the session timetable → Section 5
  9. Resources required — devices, printed instruments, backup plans
  10. Expected outcomes → Section 6
  11. Risk analysis and mitigation → Section 7
  12. Timeline — planning, pre-visit, session, analysis, report
  13. Ethical considerations — anonymity of minors, photography permission, data handling

Design rationale — what a viva examiner will ask

"Why games and not conventional teaching?"

Because the barrier beginners face is instructional, not intellectual. Games make the concept unavoidable: you cannot win the maze without an ordered sequence, so the concept is used before it is named. The problem statement sets this out in full.

"Why these five concepts?"

They are the minimum foundation every language shares — sequence, debugging, conditions, loops and variables. Remove any one of them and no program of any size can be written. Each activity teaches exactly one, so a student who misses a session still gains something from the others.

"Why a website instead of a worksheet?"

Instant feedback. A worksheet can only tell a student they were wrong after it has been marked; the activities explain the answer immediately, while the student still remembers their reasoning. The site also runs offline and needs no installation, which suits a school with limited facilities.

Deliverable 3

Final Report

The complete write-up, combining the plan with what actually happened and what was found.

Required structure

  1. Front matter — cover, certificate, declaration, acknowledgement, index
  2. Abstract — half a page summarising the project and its finding
  3. Chapter 1 — Introduction — the topic, and why it matters
  4. Chapter 2 — Literature / background — see the references
  5. Chapter 3 — Problem statement and need
  6. Chapter 4 — Objectives
  7. Chapter 5 — Methodology — including an honest statement of the design's limits
  8. Chapter 6 — The activities and the technology used
  9. Chapter 7 — Data collection — the four instruments
  10. Chapter 8 — Data analysis and findings — using the format on the Dashboard, with real data
  11. Chapter 9 — Discussion — what the findings mean, including where the project fell short
  12. Chapter 10 — Challenges and limitations
  13. Chapter 11 — Recommendations
  14. Chapter 12 — Conclusion
  15. References and Annexures

Chapter 8 is where sample data must be replaced

Every figure on the Dashboard page is currently a labelled sample. When writing Chapter 8, replace each one with the real result from the pre-test, post-test, activity scores and feedback forms. The section headings and table structures are already correct — only the numbers change.

Writing the discussion honestly (Chapter 9)

A strong report explains the result rather than just reporting it. Say which concept improved least and offer a reason. Note that a single-group design cannot separate the effect of the activities from the effect of the visit itself. Examiners reward a candidate who can state the limits of their own evidence — the methodology already does this, and Chapter 9 should follow the same tone.

Useful figures to include

  • A bar chart of pre-test vs post-test by concept
  • A table of activity scores
  • A pie or donut chart of prior coding experience
  • A table of feedback responses
  • A diagram of the session flow
  • Screenshots of the five activities (screenshot each activity page on this site)

Deliverable 4

Viva Presentation

A short deck covering the project, plus a live demonstration of the activities.

Suggested slide sequence (12–15 slides)

  1. Title slide — project name, topic 14, team, college
  2. Agenda — what you will cover
  3. The problem — syntax-first teaching creates a needless barrier
  4. Why games — experience before vocabulary
  5. Objectives — project and learning objectives
  6. Beneficiaries — Class 6–9, no prior experience assumed
  7. Methodology — the session plan and the pre/post-test design
  8. The five activities — one slide, or one slide each if time allows
  9. Live demonstration — switch to the activities page and play one activity
  10. Findings — the real pre-test vs post-test chart
  11. Feedback — what students said
  12. Challenges — what actually went wrong, and what you did about it
  13. Recommendations — what should change next time
  14. Conclusion — the barrier is pedagogical, not intellectual
  15. References and thank you

Questions an examiner is likely to ask — prepare these

  • Why did you choose these five concepts and not others?
  • How do you know the students learned anything, rather than just enjoying themselves?
  • What would you do differently if you ran the session again?
  • Which concept was hardest for the students, and why do you think that is?
  • How did you ensure no student could be identified from the data?
  • What happens to this resource now — will the school keep using it?
  • What are the limitations of your measurement?

Demonstration tip

Open the activities page before the viva starts, so no time is lost loading pages during the presentation. If the examination room has no internet, the site works entirely offline from a local copy of the files — test this in advance on the laptop you will actually use.

Before submission

Placeholder Checklist

Every item below is intentionally blank in this prototype because it can only come from the real field visit. Work through this list and tick each one off as you enter the true information.

Do not submit the prototype with the placeholders still in it

A placeholder left in place is a visible gap in the work. Search the site and your documents for the phrase [ — every one should be replaced before submission, or the section should be removed if it does not apply to your session.

A · About the school and the visit

  • ☐ School name and full address
  • ☐ Name of the principal / head
  • ☐ Name and designation of the class teacher who hosted the session
  • ☐ Date of the pre-visit and date of the actual session
  • ☐ Start and end time of the session
  • ☐ Classes and age group that participated
  • ☐ Number of students present
  • ☐ Number of working devices used, and how they were shared
  • ☐ Whether photography was permitted, with a copy of the permission

B · About the project team

  • ☐ Full names and roll numbers of all team members
  • ☐ Name of the college guide / faculty in charge
  • ☐ College name and department
  • ☐ Academic year and date of submission
  • ☐ Which team member was responsible for each part of the work

C · Data collected (replace all sample figures)

  • ☐ Number of pre-session surveys collected
  • ☐ Number of pre-tests and post-tests collected, and how many matched
  • ☐ Actual pre-test score per concept
  • ☐ Actual post-test score per concept
  • ☐ Actual change per concept
  • ☐ Actual average score per activity
  • ☐ Actual feedback responses
  • ☐ Quotes from the students' written answers (anonymised)

  • ☐ Which concept the students found hardest, and the evidence for it
  • ☐ Which of the anticipated challenges actually occurred
  • ☐ Any unforeseen difficulty, and how it was handled

  • ☐ What the team would do differently next time

E · Documentation and annexures

  • ☐ Signed certificate from the college
  • ☐ Signed declaration
  • ☐ Acknowledgement page
  • ☐ Index with correct page numbers
  • ☐ Attendance sheet (annexure)
  • ☐ Permission letter from the school (annexure)
  • ☐ Photographs with captions, if permitted (annexure)
  • ☐ Copies of all four instruments as used (annexure)
  • ☐ Complete reference list with years and editions

F · Ethics — check before submitting

  • ☐ No student's name appears anywhere in the data set
  • ☐ Pre-tests and post-tests matched by anonymous code only
  • ☐ Written permission obtained before any photograph was taken
  • ☐ No photograph published if permission was refused or not sought
  • ☐ Responses stored securely and not shared outside the project

What this project consists of

The whole project is a static website — files that run in any browser with no server, no installation and no internet connection required.

Running the project offline

Save the whole project folder to a laptop and open index.html in any browser. Everything works without an internet connection, including all five activities. This is deliberate: it means the session can go ahead in a school with no reliable network. Test it on the laptop you will actually use before the day of the visit.
