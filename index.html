A community-learning initiative that teaches the foundations of programming — sequences, conditions, loops and debugging — to school students through five hands-on games. No computers required to understand the idea; no prior coding experience required to begin.

Project Introduction

Why teach coding through games?

Computer programming is now a basic literacy, yet the way it is usually introduced makes it look like something only a few "naturally good at maths" students can do. The first lesson is often a wall of syntax — semicolons, brackets and error messages — before the student has any idea what a program actually does.

The result is predictable. Students decide early that coding is not for them, and that decision has very little to do with their ability. It happens because the concepts were never separated from the keyboard.

This project takes the opposite route. Every idea is introduced as something the student can see, play with and win before a single line of code is written. A maze teaches that order matters. A bug hunt teaches that programs fail in ways you can find. A pattern puzzle teaches that repetition can be captured in a rule. Only once the concept is understood does the technical word arrive — and by then it is a name for something the student has already done.

The idea in one sentence

Teach the thinking first, give it the name second, and let the student win at it third.

Target students

  • Class 6 to Class 9 — the age band where interest in technology forms and where abstract reasoning has developed enough for this material to land.
  • No prior programming experience assumed. Nothing in the activities requires a student to have seen code before.
  • Students who are "not good at computers" are the specific target — the success of this project is measured on them, not on the students who were already interested.
  • Mixed-ability classroom friendly — every activity gives instant feedback, so students who finish early can help others instead of waiting.

Objectives

What the project sets out to achieve

These are the project-level objectives. The student-level learning objectives, written as measurable statements, are on the Project page.

Primary objectives

  1. Introduce five core programming concepts — sequence, debugging, conditions, loops and variables — to school students through play rather than instruction.
  2. Build a complete, self-contained interactive learning resource that runs offline on a school computer or a teacher's laptop, with no installation and no internet.
  3. Measure, with a pre-test and post-test, whether a single session improves students' understanding of these five concepts.
  4. Leave the resource behind with the school so the activity can be repeated by teachers after the project team has left.

Secondary objectives

  1. Reduce the fear of error that stops beginners from experimenting — in these activities a wrong answer costs nothing and always explains itself.
  2. Give students a first vocabulary for computing that their own teachers can build on.
  3. Collect field evidence about which concepts beginners find hardest, and share it as recommendations for future sessions.
  4. Fulfil the academic requirements of the CEP while producing something genuinely useful to the community it is delivered to.
